# Initial Scout

Use for a newly supplied project or an orientation record whose intake
questions have not yet been answered.

## Cycle A — reconstruct and ask

1. Resolve the named project path and optional focus. Never guess across
   projects.
2. Inventory filenames cheaply, then inspect only likely entry documents,
   central equations, main code/results and directly referenced material.
3. Record a provisional reconstruction:
   - central problem and intended result;
   - model, assumptions and controls or variables;
   - what is established, supported, claimed, proposed, contradicted or
     unknown;
   - present mathematical, numerical and physical evidence; and
   - the decision most likely to change the research direction.
4. Create or update only `research-orientation.md` using the shared template.
5. Ask one to three questions whose answers materially affect scope,
   importance, evidence or paper direction. Do not ask the user to supply
   literature, applications or use cases the scout can investigate.
6. Tell the user to answer in the record and stop. Do not conduct the deep
   literature/application pass before this interaction unless the user already
   supplied answers or explicitly delegated the assumptions.

If the user does not care about technical choices, record defensible defaults
and continue rather than repeatedly asking.

## Cycle B — orient after answers

1. Read the user-response block without editing it.
2. Record the agent interpretation and any explicit assumptions separately.
3. Extract the transferable capability: operation, theorem, mechanism, bound,
   resource, protocol or design principle the project may provide.
4. Build a broad candidate map across the same objective, mechanism,
   mathematical structure, method, bounds/no-go results, realizations,
   downstream applications and adjacent fields.
5. Select only the lanes that can change project positioning. Search those
   lanes more deeply using current primary sources and canonical results.
6. Map each serious application using the application contract in the evidence
   rule. Reject vocabulary-only matches.
7. Formulate the strongest paper direction and no more than two credible
   alternatives. Apply the evidence gate before recommending any of them.
8. Update the compact active state and evidence ledger in the record; do not
   duplicate the entire search history.

## Initial stop rule

Stop when the record and supervisor brief can state:

- what the project presently establishes;
- what transferable capability it may produce;
- why that capability may matter and to whom;
- the strongest evidence-backed research direction;
- the most important uncertainty; and
- the next investigation most likely to change the decision.

Do not claim confirmed novelty, a confirmed gap, global optimality, physical
feasibility or venue suitability without the evidence required for that claim.
